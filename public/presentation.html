SYSTEM ARCHITECTURE

System Architecture & 3-Tier Topology

01. TRANSMITTER
Student Audio Client (/student)
  • Pre-transmission operator name/seat onboarding gate
  • Tactile circular PTT button with physical depression
  • Momentary (Hold) vs Latched (Tap) trigger modes
  • Hardware 24-segment discrete LED VU meter (-30 to +3 dB)
  • Native haptic feedback & radio key/roger sound effects
02. MUTEX ENGINE
Local Node Server (server.js)
  • Single-Speaker Concurrency Mutex prevents cross-talk
  • 60-second safety watchdog & abrupt disconnect cleanup
  • Dynamic self-signed SSL generator for mobile HTTPS
  • Strict unidirectional binary audio relay to host only
  • Local network IP auto-detection & QR generation
03. RECEIVER CONSOLE
Professor Host Console (/host)
  • Prominent illuminated studio ON AIR annunciator
  • Active student callsign in large bold typography
  • 60 FPS oscilloscope trace & 30-bar VU peak meter
  • Classroom master gain booster (0%-200%) & mute
  • Live transmission audit log with timestamps & durations

OPERATIONAL FLOW

End-to-End Operational Lifecycle

STEP 01
Scan QR & Connect

Student joins classroom Wi-Fi and scans projector QR code to access the local HTTPS link.

STEP 02
Operator Onboarding

Pre-transmission modal requires Name & Seat No before unlocking mic access. Persisted in localStorage.

STEP 03
PTT Mutex Request

Student presses tactile button. Server evaluates lock: grants exclusively or returns line busy tone.

STEP 04
Live Audio Streaming

Audio downsampled to 16kHz 16-bit mono linear PCM and relayed as binary WebSocket chunks.

STEP 05
Jitter-Free Playback

Host AudioContext schedules chunks seamlessly on timeline. Host visualizer displays waveform & 30-bar VU.

STEP 06
Release & Audit Log

Student releases switch ➔ Roger beep plays ➔ Mutex released ➔ Transmission logged with timestamp.

CORE INNOVATIONS

Technical Innovations & Problem-Solving

01. Dynamic Local SSL Generator (X.509 PKI)
CHALLENGE: Modern mobile browsers (iOS Safari & Chrome) strictly forbid getUserMedia microphone capture over plain HTTP unless on localhost.
SOLUTION: AetherMic automatically detects the physical network adapter and synthesizes in-memory X.509 certificates with Subject Alternative Names (SAN) matching the host machine local IP.
02. Single-Speaker Mutex with 60s Watchdog
CHALLENGE: Multiple students transmitting simultaneously causes catastrophic acoustic chaos, echo, and packet collision.
SOLUTION: Atomic server-side Mutex grants exclusive line access to one speaker. A 60-second safety watchdog and abrupt socket disconnect hook immediately release the lock if a student drops Wi-Fi.
03. Downsampled 16kHz PCM Binary Pipeline
CHALLENGE: Full WebRTC mesh involves heavy ICE/STUN/TURN signaling, while 48kHz stereo consumes excessive local Wi-Fi bandwidth.
SOLUTION: Raw Float32 audio is downsampled client-side to 16kHz mono 16-bit linear PCM and pushed over binary WebSockets (~32 KB/s), achieving sub-100ms latency with zero audio drift.

LIMITATIONS & ROADMAP

Current Limitations & Future Development

CURRENT LIMITATIONS
  • Self-Signed SSL Warning: Because certs are generated locally, mobile users must tap "Show Details > Visit Website" once on first launch.
  • Same Wi-Fi Subnet Required: Devices must share the same physical router or VLAN; client isolation (AP isolation) must be disabled.
  • Uncompressed PCM Bandwidth: 16kHz linear PCM uses ~256 kbps. While light for 1 speaker, compressed codecs are more efficient for large halls.
ENGINEERING ROADMAP
  • Opus WebAssembly Codec: Integrate client-side Opus compression to reduce network bandwidth by 75% for 500+ student auditoriums.
  • Live AI Closed Captions: Incorporate real-time speech-to-text (Whisper.cpp) displaying the student question on the main screen.
  • Orderly Speaker Queueing: Allow students to enter a virtual waiting line when channel is busy rather than repeatedly tapping.
